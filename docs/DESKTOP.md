# Управление компьютером в Пятнице 1.8

Используйте текущий ярлык «Пятница». Qwen 3.5 4B установлена и выбрана для анализа экрана по умолчанию. Голос и простые команды работают локально. В **Настройки → Система → Управление компьютером** можно выбрать Qwen или Codex для изображений; режим Local only полностью исключает облачные запросы. В Hybrid сложные планы могут использовать Codex через подписку ChatGPT. [Подробности подключения и замеров](CODEX.md). API key не используется.

## Примеры

- «Открой дискорд».
- «Сделай громкость 30 процентов», «Сделай музыку чуть тише».
- «Открой калькулятор, перенеси его на второй монитор и разверни».
- «Сверни его», «Восстанови калькулятор», «Закрой это окно».
- «Нажми тут продолжить», «Прокрути вниз».
- «Введи текст Привет!», «Нажми Enter» — с предварительным подтверждением.
- «Что за ошибка вылезла?» — текст интерфейса, а при необходимости один снимок выбранного окна.
- «Что у меня на экране?», «Что ты видишь?», «Прочитай текст на экране» — сразу свежий снимок монитора в Qwen, без текстового решения модели о необходимости изображения.
- «Что написано в этом окне?», «Что написано в Telegram?» — снимок конкретного окна, даже если оно перекрыто другим.
- «Что видно на втором мониторе?», «Что на всех мониторах?» — выбор области захвата.
- «Какие окна сейчас открыты?», «Какие программы у меня запущены?», «Какие приложения ты сейчас видишь?» — список пользовательских окон без Qwen, с группировкой по приложениям.
- «Какое окно сейчас активно?», «Сколько мониторов подключено?», «На каком экране сейчас это окно?» — данные Windows без модели.
- «Пятница, стоп» — остановка оставшихся действий. Голосовая активация должна быть включена. Кнопка «Стоп» работает независимо от микрофона.

«Это окно» означает текущее активное окно или последнее активное окно перед переходом в Пятницу. «Его» означает последнее успешно выбранное окно в текущем разговоре. Если найдено несколько одинаковых окон, выберите нужное вручную и скажите «это окно». Контекст окон хранится в памяти и очищается после перезапуска.

Номер дисплея берётся из имени Windows `\\.\DISPLAYn`, а аппаратный `DeviceID` сохраняется отдельно. Положение и статус основного монитора не перенумеровывают дисплеи: единственный включённый экран может иметь номер 2. «Второй экран», «второй монитор», «2 экран», «экран 2», «монитор № 2» и падежные формы обрабатывает одна функция `display_number()`. Доступные номера можно узнать командой «Сколько мониторов подключено?». Для виртуальных, клонированных и нестандартных драйверов точное совпадение с надписью «Определить» в параметрах Windows не гарантируется; собственные номера по координатам не назначаются.

## Как устроено

Существующий каталог и обработка времени, заметок, файлового поиска, музыки и других базовых команд сохранены. `desktop_agent.py` сначала разбирает детерминированные команды и цепочки. Для остальных запросов Ollama возвращает структурированный план. Pydantic проверяет типы инструментов, диапазоны и число шагов. Произвольный код и команды оболочки не исполняются.

`desktop_native.py` использует Windows API для идентификации окна по HWND, PID и времени создания процесса, положения и состояния окон, мониторов, запуска приложений и громкости. Скрытые DWM-окна (cloaked), в том числе служебные окна UWP, исключены из выбора. Проверяется появление окна, его положение/состояние и фактическая громкость.

Запуск: aliases → уже открытые окна → App Paths в реестре → стандартные пути → ярлыки «Пуск» → каталог Windows `Get-StartApps` и `shell:AppsFolder`. Русские названия «телега», «телеграм», «дискорд», «хром» приводятся к одному имени. Команда чтения каталога фиксированная: модель и пользователь не формируют PowerShell-код или аргументы запуска. Отмена прерывает и этот поиск.

Уже открытая программа считается запущенной; дубликат не создаётся. `try_focus()` пробует показать окно, но отказ foreground не отменяет успех запуска. Ответ различает: программа не найдена; запуск запрошен, но окно не появилось; программа открыта, однако Windows не дала вывести её на передний план. Для глобального ввода клавиш и координатного клика `focus()` остаётся обязательным, чтобы не отправить действие в другое приложение.

`desktop_uia.py` запускает одноразовый процесс `desktop_uia_worker.py` с лимитом 9 секунд. Тот получает ограниченное дерево UI Automation, скрывает поля паролей и использует Invoke, Selection, ExpandCollapse, Toggle, Value и Scroll. Перед действием повторно проверяется идентификатор и имя элемента. Изменение фокуса само по себе не считается подтверждением нажатия кнопки. Ввод проверяется чтением фактического значения поля.

Текст интерфейса и изображения считаются данными, а не разрешением действовать. Без подтверждения выполняются найденные через UIA явно безопасные кнопки «Назад», «Вперёд», меню, play/pause, вкладки, выбор элементов и раскрытие списков. Названия с удалением, отправкой, оплатой, сохранением/перезаписью и неизвестные кнопки требуют карточки; в распознанном окне входа или финансовом интерфейсе подтверждение сохраняется даже для вкладок. Весь ввод текста и клавиш также требует подтверждения. Согласие одноразовое, живёт две минуты. Ввод в распознанные терминалы, финансовые окна и поля паролей отключён. Нажатия по изображению всегда требуют подтверждения. UI Automation обычно не требует переводить приложение на передний план.

Снимки не делаются постоянно и не записываются на диск. `vision_request()` определяет явные просьбы посмотреть или прочитать экран. `capture_window()` снимает HWND через PrintWindow в одноразовом процессе с таймаутом 6 секунд, без вызова `focus()`. Для свёрнутого окна сохраняется WINDOWPLACEMENT, выполняется временное восстановление без активации, а в `finally` возвращаются положение и свёрнутое состояние — при успехе, ошибке и отмене. Краткое появление окна во время такого захвата возможно. `capture_screen()` снимает полный монитор, включая панель задач; по умолчанию — монитор последнего пользовательского окна. `capture_all_screens()` снимает объединённое пространство мониторов, включая отрицательные координаты. В модель передаётся PNG через Ollama `messages[].images`, только на localhost:11434. Максимальный размер передаваемого снимка окна — 1920×1440, мониторов — 2560×1600 с сохранением пропорций. Мелкий текст на общем снимке лучше читать отдельным запросом к окну.

Для нажатия сначала проверяется UIA. Если нужного элемента или доступного UIA-действия нет, программа снимает окно и просит Qwen найти границы кнопки. После подтверждения снимается свежее изображение и та же кнопка повторно ищется моделью. Проверяются подпись, сходство области кнопки и допустимое перемещение; корреляция исходной области уточняет свежие координаты. Изображения уменьшаются и размываются, небольшие изменения яркости игнорируются. Существенным считается изменение более 28% области сцены; смещение цели более 18% нормированных координат требует нового подтверждения. Непосредственно перед кликом ещё раз проверяются свежий снимок, область точки, HWND, геометрия, foreground и окно под курсором. Мигание курсора или небольшая анимация в стороне не требуют совпадения всего кадра. После клика делается контрольный снимок и отдельная проверка результата моделью. При неоднозначном UIA-совпадении, отключённой кнопке или неподтверждённом уже отправленном действии повторный клик автоматически не выполняется.

Если PrintWindow возвращает пустой кадр, ошибку или превышает таймаут, используется `MonitorCropFallback`: ImageGrab снимает физический прямоугольник видимого окна. До и после захвата проверяется, что окно полностью помещается в активных мониторах и не перекрыто окнами выше него в Z-порядке. При перекрытии или выходе за экран предлагается вывести окно на передний план; чужое содержимое не выдаётся за снимок выбранного приложения. Проверка консервативна: прозрачный overlay тоже может помешать. Отдельная старая команда «Сделай скриншот» по-прежнему сохраняет снимок по явной просьбе.

При «стоп» отменяется запрос к модели, завершается зависший процесс UIA/захвата/поиска приложений и не запускаются дальнейшие шаги. Уже переданное Windows одиночное действие нельзя отозвать. Слушатель остановки использует Vosk без ожидания Whisper. Микрофон остаётся тем, который выбран в настройках. Текстовое «Пятница, стоп» также обрабатывается до блокировки занятого чата.

Для экономии 8 ГБ видеопамяти процесс выразительного голоса освобождается перед запросом Qwen, а модель понимания выгружается перед новым выразительным голосовым ответом. Это может увеличить задержку первого ответа. Готовые голосовые образцы остаются быстрыми.

## Ограничения рабочей версии

- Это ограниченный исполнитель до восьми шагов, а не универсальный автономный агент с бесконечным повторным планированием.
- У нестандартных приложений, игр, удалённых рабочих столов и окон администратора UI Automation может не работать. Приложение не повышает свои права.
- Для клика по изображению координаты могут быть неточными. После клика делается контрольный снимок, локальная модель сравнивает состояние до и после и объясняет, виден ли нужный результат. При одинаковом изображении, неуверенности или закрывшемся окне цепочка останавливается. Это вероятностная проверка; подтверждённые Windows API состояния надёжнее. Второй клик по старым координатам запрещён: нужна новая команда с новым снимком.
- После обычного UIA-нажатия проверяется наблюдаемое изменение интерфейса. Это не является доказательством завершения внешней операции на сервере.
- Ввод поддерживается в доступных редактируемых полях UIA. Если полей несколько, нужно назвать нужное. Текст заменяет значение поля; это указано в карточке.
- Отдельных инструментов удаления файлов, покупки или отправки сообщений нет. Доступны проверяемые действия в интерфейсе с подтверждением; назначение неизвестной кнопки тоже требует подтверждения.
- Модель может ошибиться в понимании или не сформировать допустимый план. В этом случае действия не запускаются. История планировщика ограничена несколькими последними сообщениями; память окон отдельно привязана к разговору.
- Активное окно отслеживается по метаданным; экран не записывается. Вмешательство пользователя и изменение интерфейса могут отменить текущий шаг.

## Проверки

Автоматические проверки: `.venv/Scripts/python.exe -m pytest -q`, `npm run build`.

Реальные проверки: `tests/desktop_integration.py` (собственное Win32-окно, UIA, подтверждение/отказ, ввод, калькулятор, доступные мониторы, контекст, громкость с восстановлением уровня), `tests/desktop_model_check.py` (установленная Qwen и синтетическое изображение), `tests/desktop-native.cjs` (готовое Electron-приложение с отдельной историей и тестовым окном). Голосовые и остальные регрессии последовательно запускает `.venv/Scripts/python.exe tests/run_regressions.py`. Параметр `FRIDAY_DATA_DIR` позволяет изолировать базу backend; по умолчанию используется обычный `data/`.

Тесты интерфейса используют собственные временные окна, историю и профиль. Перед нативными UI-проверками нужно закрыть Пятницу, чтобы не подменять запущенный пользовательский экземпляр.

Дополнительные проверки:

```powershell
.venv/Scripts/python.exe -m pytest tests/test_desktop_reliability.py -q
.venv/Scripts/python.exe -m pytest tests/test_desktop_resilience.py -q
.venv/Scripts/python.exe tests/desktop_capture_integration.py
.venv/Scripts/python.exe tests/desktop_model_cancel.py
.venv/Scripts/python.exe tests/desktop_vision_integration.py
.venv/Scripts/python.exe tests/desktop_apps_integration.py
.venv/Scripts/python.exe tests/desktop_shell_integration.py
```

`desktop_vision_integration.py` проверяет перекрытое окно без фокуса, отдельный vision-скрипт с реальной Qwen 4B, чтение ошибки 810, отсутствие UIA, анимацию и смещение кнопки после подтверждения, реальный клик и проверку результата. `desktop_capture_integration.py` проверяет Telegram, Discord, Chrome, калькулятор и Win32-окно: PrintWindow, сворачивание после анализа, реальный ImageGrab при искусственном отказе PrintWindow, локальные запросы и разные уровни риска UIA. Снимки приложений остаются в памяти, не отправляются модели и не сохраняются. `desktop_apps_integration.py` проверяет открытие Telegram/Discord, повторный запуск и искусственный отказ фокуса, управление калькулятором. Исходное положение калькулятора восстанавливается, созданный тестом калькулятор закрывается. Для проверки именно двух физических дисплеев оба должны быть активны.

`desktop_shell_integration.py` требует закрытого калькулятора. Он искусственно отключает поиск EXE, запускает настоящий Store-калькулятор через AppsFolder, проверяет HWND и закрывает своё тестовое окно.

## Vision отдельно от Пятницы

Ollama должна быть запущена; Пятница запускает её автоматически. Сам скрипт не использует сервер Пятницы, голос, историю или планировщик. Модель берётся из текущих настроек, по умолчанию `qwen3.5:4b`. Выполняется один снимок и один запрос. Даже если анализ экрана отключён в настройках Пятницы, явный запуск этого диагностического скрипта делает снимок.

```powershell
.venv/Scripts/python.exe scripts/test_vision.py
.venv/Scripts/python.exe scripts/test_vision.py --scope window --window calculator
.venv/Scripts/python.exe scripts/test_vision.py --scope monitor --monitor 2
.venv/Scripts/python.exe scripts/test_vision.py --scope all_screens
```

По умолчанию вопрос: «Опиши, что видно на изображении». Есть `--question` и `--model`. Сырой текст ответа выводится в stdout, диагностика — в stderr. Ошибка завершает тест с кодом 1; Ctrl+C — 130. Файл изображения не создаётся.

## Локальный журнал диагностики

Закройте Пятницу и запустите из корня проекта:

```powershell
./scripts/start_debug.ps1
Get-Content ./data/backend.log -Tail 100 -Wait
```

Либо задайте `$env:FRIDAY_DEBUG='1'` перед обычным запуском приложения или backend. Видны стадии `[VOICE]`, `[INPUT]`, `[ROUTER]`, `[TOOL]`, `[RESOLVER]`, `[LAUNCH]`, `[VERIFY]`, `[FOCUS]`, `[SCREEN]`, `[AI]`, `[AI RESULT]`, `[RESULT]`, `[STOP]`. Для снимка выводятся тип, размеры, HWND/номер монитора и метод `PrintWindow`, `MonitorCropFallback` или `ImageGrab`. Для запросов к модели — выбранное имя и `image_attached=true/false`. Применяется закрытый список допустимых технических полей: полные фразы STT, вводимый текст, заголовки окон, значения полей, ответы модели, пути и текст исключений скрываются; остаются длина, тип действия, статус и числовые показатели. Отдельный явно запущенный `test_vision.py` по-прежнему выводит сырой ответ в консоль. Весь `data/` исключён из Git. Чтобы выключить режим, перезапустите приложение с удалённой переменной `FRIDAY_DEBUG`.
