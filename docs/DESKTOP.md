# Управление компьютером в Пятнице 1.6

Используйте текущий ярлык «Пятница». Модель Qwen 3.5 4B уже установлена. Интернет нужен только для загрузки другой модели через **Настройки → Система → Управление компьютером**. Голос, распознавание, понимание текста и изображений работают на этом ПК; платные API не используются.

## Примеры

- «Открой дискорд».
- «Сделай громкость 30 процентов», «Сделай музыку чуть тише».
- «Открой калькулятор, перенеси его на второй монитор и разверни».
- «Сверни его», «Восстанови калькулятор», «Закрой это окно».
- «Нажми тут продолжить», «Прокрути вниз».
- «Введи текст Привет!», «Нажми Enter» — с предварительным подтверждением.
- «Что за ошибка вылезла?» — текст интерфейса, а при необходимости один снимок выбранного окна.
- «Пятница, стоп» — остановка оставшихся действий. Голосовая активация должна быть включена. Кнопка «Стоп» работает независимо от микрофона.

«Это окно» означает текущее активное окно или последнее активное окно перед переходом в Пятницу. «Его» означает последнее успешно выбранное окно в текущем разговоре. Если найдено несколько одинаковых окон, выберите нужное вручную и скажите «это окно». Монитор 1 — основной, остальные нумеруются слева направо; это может отличаться от номеров в параметрах Windows. Контекст окон хранится в памяти и очищается после перезапуска.

## Как устроено

Существующий каталог и обработка времени, заметок, файлового поиска, музыки и других базовых команд сохранены. `desktop_agent.py` сначала разбирает детерминированные команды и цепочки. Для остальных запросов Ollama возвращает структурированный план. Pydantic проверяет типы инструментов, диапазоны и число шагов. Произвольный код и команды оболочки не исполняются.

`desktop_native.py` использует Windows API для идентификации окна по HWND, PID и времени создания процесса, положения и состояния окон, мониторов, запуска приложений и громкости. Названия программ разрешаются существующим каталогом и установленными ярлыками. Проверяется появление окна, его положение/состояние и фактическая громкость.

`desktop_uia.py` запускает одноразовый процесс `desktop_uia_worker.py` с лимитом 9 секунд. Тот получает ограниченное дерево UI Automation, скрывает поля паролей и использует Invoke, Selection, Toggle, Value и Scroll. Перед действием повторно проверяется идентификатор и имя элемента. Изменение фокуса само по себе не считается подтверждением нажатия кнопки. Ввод проверяется чтением фактического значения поля.

Текст интерфейса и изображения считаются данными, а не разрешением действовать. Нажатия с возможными последствиями, весь ввод текста и клавиш требуют карточки подтверждения. Согласие одноразовое, живёт две минуты; смена окна или интерфейса после карточки отменяет действие. Ввод в распознанные терминалы, финансовые окна и поля паролей отключён. Нажатия по изображению всегда требуют подтверждения. UI Automation обычно не требует переводить приложение на передний план.

Снимки не делаются в фоне и не записываются на диск. При визуальном резервном пути локальная модель получает JPEG выбранного окна; перед кликом после подтверждения делается контрольный снимок. Если изображение изменилось, клик не выполняется. Отдельная старая команда «Сделай скриншот» по-прежнему сохраняет снимок по явной просьбе.

При «стоп» отменяется запрос к модели, убивается зависший UIA-процесс и не запускаются дальнейшие шаги. Уже переданное Windows одиночное действие нельзя отозвать. Слушатель остановки использует Vosk без ожидания Whisper. Микрофон остаётся тем, который выбран в настройках.

Для экономии 8 ГБ видеопамяти процесс выразительного голоса освобождается перед запросом Qwen, а модель понимания выгружается перед новым выразительным голосовым ответом. Это может увеличить задержку первого ответа. Готовые голосовые образцы остаются быстрыми.

## Ограничения рабочей версии

- Это ограниченный исполнитель до восьми шагов, а не универсальный автономный агент с бесконечным повторным планированием.
- У нестандартных приложений, игр, удалённых рабочих столов и окон администратора UI Automation может не работать. Приложение не повышает свои права.
- Для клика по изображению координаты могут быть неточными. После клика делается контрольный снимок, локальная модель сравнивает состояние до и после и объясняет, виден ли нужный результат. При одинаковом изображении, неуверенности или закрывшемся окне цепочка останавливается. Это вероятностная проверка; подтверждённые Windows API состояния надёжнее. Второй клик по старым координатам запрещён: нужна новая команда с новым снимком.
- После обычного UIA-нажатия проверяется наблюдаемое изменение интерфейса. Это не является доказательством завершения внешней операции на сервере.
- Ввод поддерживается в доступных редактируемых полях UIA. Если полей несколько, нужно назвать нужное. Текст заменяет значение поля; это указано в карточке.
- Отдельных инструментов удаления файлов, покупки или отправки сообщений нет. Доступны проверяемые действия в интерфейсе с подтверждением; назначение неизвестной кнопки тоже требует подтверждения.
- Модель может ошибиться в понимании или не сформировать допустимый план. В этом случае действия не запускаются. История планировщика ограничена несколькими последними сообщениями; память окон отдельно привязана к разговору.
- Активное окно отслеживается по метаданным; экран не записывается. Вмешательство пользователя и изменение интерфейса могут отменить текущий шаг.

## Проверки

Автоматические проверки: `.venv/Scripts/python.exe -m pytest -q`, `npm run build`.

Реальные проверки на этом ПК: `tests/desktop_integration.py` (собственное Win32-окно, UIA, подтверждение/отказ, ввод, калькулятор, два монитора, контекст, громкость с восстановлением исходного уровня), `tests/desktop_model_check.py` (установленная Qwen и синтетическое изображение), `tests/desktop-native.cjs` (готовое Electron-приложение с отдельной историей и тестовым окном). Голосовые регрессии: `tests/wake-ui.cjs` и `tests/voice-native.cjs`.

Тесты используют собственные временные окна, историю и профиль. Перед нативными UI-проверками нужно закрыть Пятницу, чтобы не подменять запущенный пользовательский экземпляр.
