# Codex в Пятнице

Проверено с официальным `@openai/codex` **0.154.0**, Node 24.15.0 и существующим входом **ChatGPT Plus**. Пятница вызывает нативный CLI напрямую из Python: `codex exec`, prompt в UTF-8 stdin, штатный `--image`, JSONL и `--output-schema`. SDK и отдельный сервер не нужны. Существующая авторизация не копируется, не сбрасывается и не удаляется; CLI сам обновляет её штатным способом.

Используется лимит Codex подписки ChatGPT. Приложение не подключается напрямую к платному API, не принимает API key и исключает унаследованные переменные API-авторизации из окружения дочернего CLI. Перед запросом проверяется именно ChatGPT login. На другом компьютере нужны `npm install -g @openai/codex@0.154.0` и `codex login`; на этом всё уже установлено. Статус: `codex login status`.

Официальные документы: [неинтерактивный CLI](https://learn.chatgpt.com/docs/non-interactive-mode), [авторизация](https://learn.chatgpt.com/docs/auth), [настройки](https://learn.chatgpt.com/docs/config-file/config-reference).

## Маршруты

| Запрос | Исполнитель |
| --- | --- |
| Открыть приложение, громкость, перенос окна, список окон/дисплеев | Обычный локальный код |
| Найти или нажать подписанную кнопку | Сначала UI Automation |
| Простой нераспознанный языковой запрос | Ollama, выбранная локальная Qwen |
| Анализ снимка, координаты при недоступной UIA | Qwen по умолчанию; Codex при выборе в настройках |
| Сложный план с «сначала… затем…», «разберись…» | Codex Luna; при отказе — Qwen |
| Telegram messaging | Существующий отдельный локальный workflow с подтверждением отправки |

В **Local only** облачных запросов нет. **Hybrid** — стандартный режим: отдельный переключатель «Анализ экрана» выбирает **Qwen — на этом ПК** или **Codex — через ChatGPT**. После реальных замеров и выбора пользователя по умолчанию оставлена Qwen. **Codex vision** принудительно использует Codex для изображения. Облачная модель по умолчанию `gpt-5.6-luna`, reasoning `low`. Terra выбирается только вручную, Sol не используется. Qwen `qwen3.5:4b` сохранена; 9B не устанавливается автоматически. При выбранной Qwen её ошибка сама по себе не отправляет снимок в облако; переключение выполняется явно.

«Найди кнопку Продолжить» ищет через UIA, затем по снимку, и сообщает результат без нажатия. «Нажми кнопку Продолжить» выполняет существующую цепочку с проверками. Все планы проходят строгую JSON Schema и Pydantic-валидацию; модель не определяет, было ли исполнено Windows-действие. Опасные действия и координатный клик сохраняют подтверждение пользователя.

## Изоляция, остановка, ошибки

CLI запускается в отдельной временной папке с `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, read-only и запретом подтверждений со стороны CLI. Отключены shell, браузер, computer use, apps, плагины, hooks, multi-agent, memories и инструменты установки. У Code Mode выключен host и запрещён in-process fallback. Таким образом, Codex используется как наблюдатель/планировщик; основной конфиг пользователя и инструменты основного Codex не меняются. Временные изображения и схема удаляются в `finally`, включая отмену и ошибки.

Обычный запрос Codex ограничен 45 секундами, Ollama — 120 секундами, включая одну попытку исправления неправильного формата. Прогрессивный анализ может сделать два последовательных image-запроса. Одновременно Пятница выполняет одну команду. «Пятница, стоп», Esc и кнопка остановки отменяют запрос, завершают только дочерний процесс Пятницы и не запускают fallback после отмены. Новая обычная команда во время выполнения получает прежнее сообщение ожидания; автоматической замены команды нет.

При ошибке сети, авторизации, лимита, таймауте или неправильной схеме Codex включается локальный fallback, если переключатель включён. Если оба провайдера недоступны, выводится понятная ошибка; deterministic Windows tools продолжают работать. `Connected via ChatGPT` подтверждает вход CLI, а не гарантирует доступность интернета в следующую секунду. Статус последней ошибки показывается до успешного запроса. Вход проверяется с кэшем 60 секунд.

## Снимки и замеры

Оригинал захвата сохраняется в памяти без предварительного уменьшения. Для общего анализа используется длинная сторона до 1440 px с сохранением пропорций. Для текста сохраняется PNG; тяжёлый PNG при существенной экономии заменяется JPEG quality 90 без уменьшения цветовой детализации. Например, реальный снимок 2560×1440 отправлен как 1440×810, 529 КБ вместо примерно 2 МБ PNG.

Если обзор показывает, что мелкий текст не читается, модель возвращает область, из оригинала вырезается фрагмент и отправляется второй запрос. Для найденной кнопки на большом снимке дополнительно уточняется положение в увеличенном фрагменте; координаты переводятся обратно в исходное окно. После подтверждения цель заново находится на свежем снимке и проверяется существующим Action Engine. Монитор 2 и экран 2 используют один Windows display id; все мониторы снимаются только по соответствующей просьбе.

`FRIDAY_DEBUG=1` включает безопасные `[AI]`, `[CODEX]`, `[FALLBACK]`, `[VISION]`, `[VISION CHAIN]`: модель, провайдер, размеры, размер кодирования, `capture_ms`, `preprocess_ms`, `upload_start_ms`, `request_started_ms`, `first_response_ms`, `total_ms`. Фразы, сообщения, ответы модели и изображение в эти логи не пишутся. `capture_ms=0` у прямого вызова провайдера означает, что захват был выполнен снаружи и время ему не передали.

`upload_start_ms` — время подготовки и старта транспорта, **не отдельное измерение сетевой загрузки**: CLI его не предоставляет. CLI JSONL отдаёт готовое сообщение, поэтому `first_response_ms` у Codex — первое целое сообщение. Ollama стримит токены, её `first_response_ms` — первый токен содержимого. UI получает только проверенный ответ; посимвольного стриминга JSON-планов в интерфейс нет.

## Самостоятельный тест

Из корня проекта:

```powershell
.venv\Scripts\python.exe scripts/test_codex_vision.py --monitor 1
.venv\Scripts\python.exe scripts/test_codex_vision.py --window calculator
.venv\Scripts\python.exe scripts/test_codex_vision.py --compare --runs 3 --monitor 1
```

Один снимок захватывается один раз. Для сравнения обе модели получают одинаковые изображение и вопрос, три раза по очереди. Терминал показывает ответ, модель, размеры и время. `data/codex-vision-benchmark.json` содержит только размеры и замеры, без ответов и снимка. Общий видимый экран может содержать личную информацию: этот диагностический запрос отправляет его выбранному Codex так же, как команда анализа экрана в Hybrid.

Замер 15.09.2026 на этом ПК, прогретые модели, рабочий стол 2560×1440 → 1440×810, одинаковый вопрос:

| Провайдер | Полные ответы, с | Медиана, с | Первый ответ, медиана, с |
| --- | --- | --- | --- |
| Codex Luna, low | 5,812 / 5,447 / 5,295 | **5,447** | 5,421 (целое сообщение) |
| Qwen 3.5 4B | 3,638 / 3,402 / 3,291 | **3,402** | 2,287 (первый токен) |

На этом простом снимке **Qwen быстрее примерно в 1,60 раза**. Luna не стала быстрее автоматически. Результат зависит от сложности, прогрева, сети и загрузки GPU; кэши между прогонами не очищались. Холодный локальный запрос к тестовому окну при проверке fallback занял около 10,4 с, следующий — около 3,4 с.

Дополнительно после запуска финального приложения через обычный `/api/chat` прочитан текст одного тестового окна: Qwen — 10,70 с, Luna — 7,06 с, включая захват и подготовку. Это отдельная проверка после запуска, не медиана прогретого benchmark. Оба ответа правильно прочитали код 810. Текстовая команда «Пятница, стоп» через тот же API завершила активный Codex-запрос за 88 мс. После проверки сохранён выбор Qwen; тестовый разговор удалён.

## Проверки

`tests/test_ai_providers.py` проверяет маршруты, отсутствие API-auth в child env, схемы, недоступную сеть/провайдеры, лимиты, таймаут, отмену реального тестового subprocess, размер 2K, crop, координаты и redaction.

Итоговая проверка: **448 pytest-тестов и 26 сценариев `tests/run_regressions.py` прошли**. Дополнительно выполнены реальные capture/vision/Codex/packaged-shell проверки. Проверены прежние запись речи, локальная озвучка, wake word, работа в свёрнутом окне, Telegram без отправки новых сообщений и сохранение настроек провайдера.

`tests/codex_windows_integration.py` вызывает настоящий CLI с ChatGPT login, анализирует Win32-окно через Luna, уточняет маленькую кнопку, проверяет локальный fallback с настоящей Ollama и отмену настоящего Codex-запроса. Проверены реальные дисплеи 1 (2560×1440) и 2 (1920×1080); команда «стоп» завершила запрос примерно за 84 мс в одном прогоне.

`tests/desktop_capture_integration.py` проверяет Telegram (включая повторное открытие из трея), Discord, Chrome, калькулятор, обычное Win32-окно, PrintWindow, MonitorCropFallback, повторное сворачивание, UIA и перенос между мониторами. Ошибки сети/лимита для fallback воспроизводятся внедрением отказа, без отключения сети пользователя и без намеренного расходования всей подписки.

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe tests/codex_windows_integration.py
.venv\Scripts\python.exe tests/desktop_capture_integration.py
node tests/codex-ui.cjs
```

Закрытые/защищённые Windows экраны, UAC, DRM и перекрытое окно при неработающем PrintWindow по-прежнему могут быть недоступны для захвата. Координатный поиск остаётся вероятностным и требует подтверждения. Terra подготовлена к ручному выбору; приведённые реальные замеры относятся к Luna.
