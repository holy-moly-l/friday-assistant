# Формулировка сообщений Telegram

`backend/message_composer.py` — отдельный текстовый компонент перед поиском чата и `prepare` в `TelegramMessages`. Получатель определяется прежним parser/workflow; Composer не получает инструментов, истории чата или управления Telegram. Его результат имеет строгую схему `text`, `needs_clarification`; наружу компонент также возвращает признак `verbatim`.

Используется только локальная **qwen3.5:4b** через Ollama, независимо от выбранного провайдера экрана и режима Hybrid/Codex vision. `think=false`, temperature 0, context 4096, максимум 768 токенов для обычного сообщения. Для длинного текста контекст расширяется до 8192, ответ — до 3072 токенов. Дополнительных моделей или зависимостей не требуется. Таймаут одного запроса 25 с, всей формулировки 35 с; при неправильной схеме или подозрительном результате допускается одна строгая повторная попытка.

Примеры:

| Команда | Подготовленный текст |
| --- | --- |
| Напиши Насте, что пусть приедет сегодня в 12 часов | Приезжай сегодня в 12 часов. |
| Скажи Саше, чтобы он купил хлеб | Купи хлеб. |
| Спроси Настю, сможет ли она приехать завтра | Сможешь приехать завтра? |
| Скажи Насте, что она забыла ключи | Ты забыла ключи. |
| Скажи Насте, что я забыл ключи | Я забыл ключи. |
| Скажи Насте, что Саша уже приехал | Саша уже приехал. |

`дословно`, `слово в слово`, `именно так`, `как есть` после имени получателя обходят Qwen. Слова, регистр, внутренняя пунктуация и переносы строк остаются такими, какими их передали в parser после STT. Начальные/конечные пробелы и разделитель команды отделяются от сообщения. Слово «что» само по себе не включает дословный режим. «Отправь как есть: …» использует только последний проверенный чат текущего разговора; без него Пятница уточняет получателя.

Проверяются числа с их знаками, время и даты, ссылки/email, имена и их роли, содержательные слова с учётом склонения, отрицания и их привязка к действию, предлоги, условность, первое лицо и времена глаголов. Для естественного повелительного наклонения допускается смена вида «приехать/приезжать», «прийти/приходить». «Я приеду» и «Приеду» допустимы, потому что первое лицо выражено глаголом. Проверки намеренно консервативны: даже смысловой синоним может потребовать уточнения.

Это защита от типичных искажений, а не математическая гарантия смысла. Финальный текст всегда показывается в существующем подтверждении. Если модель недоступна или результат не прошёл проверки, Telegram не открывается, текст хранится в памяти в ожидании уточнения. Можно сказать «отправь дословно»: будет подготовлен исходный текст, снова с обязательным подтверждением. Автоматического cloud fallback нет.

После формулировки сохранены прежние шаги: уникальный получатель → проверенный чат → черновик → одноразовое подтверждение → Send → новое точное сообщение в истории с подтверждённым статусом. «Нет», «отмена» и «Пятница, стоп» не отправляют сообщение. Стоп отменяет также HTTP-запрос формулировки. В логе `[MESSAGE_COMPOSER]` только провайдер, модель, длины, длительность и `verbatim`; содержимое сообщения не выводится.

Учтён заголовок Telegram с несколькими аккаунтами: `чат @ аккаунт`. Разделитель распознаётся по служебному маркеру направления текста, обычный `@` внутри имени не обрезается. Идентификатор аккаунта привязывается к проверенному чату; переключение аккаунта после подготовки отменяет отправку. Формат сверён с [MainWindow::updateTitle в Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/window/main_window.cpp).

Правки стиля внутри открытого подтверждения («помягче», «покороче», «добавь…») пока не реализованы. Можно нажать «Нет» и дать новую полную команду, например «Напиши ей дословно: приезжай к двенадцати». Контекст проверенного получателя сохраняется; новый текст снова требует подтверждения.

Проверки без отправки:

```powershell
.venv\Scripts\python.exe -m pytest tests/test_message_composer.py tests/test_telegram_messages.py -q
.venv\Scripts\python.exe tests/message_composer_integration.py
node tests/telegram-ui.cjs
```

Реальный локальный тест проверяет 19 формулировок и отмену активного Ollama-запроса. Отчёт `data/message-composer-check.json` содержит только номера тестов, длины и время. Содержимое тестовых сообщений в отчёт не записывается.

```powershell
# Реальный Telegram: черновик и отмена, без отправки
.venv\Scripts\python.exe tests/message_composer_integration.py --telegram
# Только с разрешением владельца: одна отправка в собственное «Избранное»
.venv\Scripts\python.exe tests/message_composer_integration.py --telegram --send-self
```

Перед отправкой тест проверяет `self_chat`, итоговый текст и черновик; после отправки работает обычная проверка новой записи в истории. Чаты контактов в этом тесте не используются.

Проверено 22.09.2026: **517 pytest-тестов**, браузерный сценарий подтверждения и все **19 реальных формулировок Qwen** прошли. Медиана последнего прогона — **3,08 с**, короткие прогретые запросы обычно 2,7–3,4 с; холодный первый запрос — 14,7 с, длинный пример — 6,9 с. Отмена активного локального запроса — 39 мс. В настоящем Telegram проверены отказ, стоп и одна подтверждённая отправка в «Избранное» с проверкой новой записи истории. Контактам тестовые сообщения не отправлялись.
