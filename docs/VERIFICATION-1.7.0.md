# Проверка Telegram messaging — 1.7.0

Дата: 15 сентября 2026. Windows, установленный Telegram Desktop **7.2.8.0**.
Имена контактов, username, переписка и снимки личного интерфейса в репозиторий не включены.

## Реальная проверка

С явного разрешения пользователя выполнены **две отправки указанному им контакту**:
«Напиши в Telegram @username: …» и «Ответь Насте, что …». После совпадения username
в поле профиля оба черновика прошли одноразовое подтверждение; оба новых исходящих
сообщения найдены в истории с точным текстом. Вторая команда использовала проверенный
username из контекста. Самому контакту отправлены только два сообщения с пояснением теста.

Отдельно разрешённый тест в «Избранном» выявил особенность Telegram: сообщение самому себе
имеет статус «Получено». Проверка исправлена исключительно для чата, открытого через
семантический тип «Избранное» или стандартную команду Telegram Ctrl+0. Одного названия
«Избранное» недостаточно. Повторной отправки для исправления проверки не делалось.

`tests/telegram_windows_integration.py` прошёл на настоящем приложении:

- Уже открытый Telegram; свёрнутое окно; закрытое окно с повторным открытием (обычное поведение Telegram / трей).
- Поиск отсутствующего контакта; два одинаковых имени с разными идентификаторами.
- Поиск уникального контакта, UIA Invoke, совпадение заголовка; без набора и отправки этому контакту.
- Буквальные `{Enter}` и перевод строки в черновике: клавиша Enter не нажимается, сообщения в истории не появляются.
- Подготовка черновика без отправки; «Нет»; «Стоп»; очистка только своего неизменённого черновика.

По умолчанию этот скрипт не отправляет сообщения. В итоговом отчёте автоматического прогона
отправка имеет статус SKIP; две реальные отправки контакту проведены отдельно по явному разрешению.
Для самостоятельного теста одной отправки себе есть явный флаг `--send-self`.

## Автоматические проверки

- **413 pytest-тестов прошли**. Включены формулировки, склонения, буквальный текст,
  контекст и его срок жизни, неоднозначные получатели, точный username, чужой/изменённый
  черновик, повтор nonce, истечение подтверждения, отсутствие Qwen, отмена и обрыв потока,
  новое/старое совпадающее сообщение, статус отправки, приватность диагностических логов.
- **23 прежних интеграционных сценария прошли** через `tests/run_regressions.py`:
  Windows tools/UIA, локальная модель и остановка модели, каталог, внешний вид, микрофон,
  STT, Vosk wake word, голоса и отмена TTS, настоящий Electron и работа в свёрнутом состоянии.
- **2 новых интеграционных сценария прошли после исправлений**:
  `telegram-ui.cjs` (браузер + настоящий API/workflow, подменён только Telegram) и
  `telegram_windows_integration.py` (установленный Telegram).
- `npm run package`: TypeScript, Vite и сборка EXE 1.7.0 завершились успешно.

При полном прогоне новые тесты выявили отмену очистки черновика вместе с HTTP-потоком
и зависимость тестовой навигации от foreground. Очистка теперь защищена от отмены
группы задач Starlette, оставаясь ограниченной по времени. Выход из поиска выполняется
через UIA-кнопку «Отменить поиск», «Избранное» открывается через семантический тип чата;
Ctrl+0 остаётся запасным вариантом с обязательной проверкой фокуса.

## Границы реализации

- Сценарий полностью локальный: установленный Telegram Desktop, Windows UI Automation,
  словарь pymorphy3. Нет Bot API, облачного распознавания намерения или вызова Qwen для отправки.
  Сам Telegram, разумеется, использует своё сетевое подключение.
- Проверены русские подписи Telegram 7.2.8. Английские подписи предусмотрены, но отдельно не проверялись.
- Нужны доступные поля чата, профиля и истории. Результаты глобального поиска, которые Telegram
  не раскрывает как обычные чаты, не используются для слепой отправки: может понадобиться
  сначала добавить контакт/открыть диалог вручную. Вложения не реализованы.
- UIA Invoke имеет приоритет; Legacy Accessibility — запасное нажатие, Ctrl+0 — запасной
  переход в «Избранное». Координатного/vision fallback для отправки нет: он не доказывает получателя.
- Контекст живёт в памяти одного разговора 10 минут. После перезапуска или при одинаковых
  именах без ранее проверенного username нужно новое уточнение.
- Если отправка уже запрошена, отмена останавливает дальнейшие шаги и проверку, но не отзывает
  сообщение. Неопределённый результат не вызывает автоматическую повторную отправку.
- Проверка подтверждает появление сообщения в истории Telegram, а не прочтение адресатом.
- Если пользователь сменил чат или отредактировал черновик, Пятница не очищает чужой текст.

Исходная архитектура deterministic tools → UIA → локальный Qwen/vision сохранена;
Telegram подключён отдельным обработчиком до общего планировщика.
